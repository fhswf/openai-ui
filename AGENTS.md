## conventional commits

In this project, we use [conventional commits](https://www.conventionalcommits.org/en/v1.0.0/) to define the commit history. This allows us to automatically generate a changelog and determine the next version number based on the types of commits made. 
We use the following commit types:

- `feat`: A new feature
- `fix`: A bug fix
- `docs`: Documentation changes
- `style`: Code style changes (formatting, missing semi-colons, etc.)
- `refactor`: Code changes that neither fix a bug nor add a feature
- `test`: Adding or updating tests. You recognize test files by the `*.test.ts` or `*.spec.ts` suffix.
